# P5 · 命令注入與 C 程式碼邏輯追蹤（25 分鐘）

> Pwn 模組這章的「命令注入」跟 Web 的命令注入不完全同一件事：這裡多是「**程式內部呼叫 `system()`**，而該函數的參數被攻擊者影響」。
> 另一重點是「**C 程式碼邏輯追蹤**」——拿到一個 strip 過的 binary，如何在 10 分鐘內看懂它在做什麼。

---

## 1 · `system()` 在 Pwn 中的三大用途

```text
①  讓程式「跑 shell」而不用寫 shellcode —— 當 binary 已 import libc 但沒呼叫 system()
②  直接跳 `system("/bin/sh")`（ret2libc，P4 已講）
③  跳 GOT 中 `system` 對應的 libc 位址（覆寫 GOT 後呼叫 system(...)）
```

> 常泛用一條心法：**能不寫 shellcode就不要寫**。用現成 libc 的 `system` 比 shellcode 穩；shellcode 只在「NX 關閉（可執行棧）」時才有優勢。

## 2 · 反編譯 / 逆向 C 程式的流程

### 2.1 第一步：看 main

```bash
objdump -d -M intel ./pwn | grep -A 30 '<main>:'
```

> strip 過的（無 main symbol）， pwntools `ELF().functions` 儘管已動態。  另一`: gdb inside pwndbg`用 `entry-points` 定 main。

### 2.2 第二步：找輸入/increcement 面點

關鍵函數（決定這題怎麼打）：

| 函數 | 意味 |
|---|---|
| `read(0, buf, N)` / `scanf` | 直接輸入點：溢位的可能 |
| `gets(buf)` | 級別最極端：無長度 |
| `strcpy/strcat/sprintf` | 緩衝溢位主流 |
| `strtol/atoi` | 數字轉換（off-by-one/負數） |
| `printf(name)` | 可能是格式化字串 |

### 2.3 第三步：邏輯追蹤 tactic

```text
① 試「錯誤輸入」重新構建 crash
② `ltrace` / `strace` 觀察運行中的呼叫:
     strace -f ./pwn     # 看syscall
     ltrace ./pwn        # 看 libc 呼叫（如 scanf 或 printf 參數）
③ 反編譯器（ghidra）或 pwntools  aid（不會得USPush）
```

## 3 · 「問題原生函數「不服」」的排查流（邏輯追蹤）

常見三類「猜不出來的營為」，用這個順序查：

| 現象 | 原因猜測 | 驗證手段 |
|---|---|---|
| 未 shell、程式靜默 | 幾乎是 `setbuf`/`buffer` 出現差異 | `2>/dev/null` 改變 |
| EOF 之後永遠結束 | `setbuf(NULL)` | 滾動送入特定數量的 echo |
| 遠端與本地 crash 位址不同 | libc 版本差 | `checksec` 路徑 |

> PWn 這章的「問題-tracing」原則跟 Web 是同級：**先看訊息可見度（回應）再重構行為**。不用瞎猜。

## 4 · Pwn 「命令注入」的payload 円本身

跟 Web 不同：Pwn 題的「命令注入」往往是以 **`system(user_content)` 的形式出現在程式中**：

```c
if (strcmp(user, "admin")==0)  {
   char cmd[64]; sprintf(cmd, "echo %s", user); system(cmd);
}
```

這裡 `user` 需要 `; cat flag` 形式的注入，是「Web 命令注入的 C 版」；
此處成為 pwn 的題型。

### 4.1 `setuid` 題集中「多一層」（有視 root）

```c
if (geteuid() == 0) { system("/bin/sh"); }
```

> 規則：賽場 Linux 用戶有 `suid` 位，會在 `exec` 後繼續; 當一個 binary 加 setuid 之後
> 的 `geteuid()` 會 = root → system("/bin/sh") → flag。

## 5 · P5 的「實際學法」

> 這章重點不是死知識，而是「堅固的工具箱」。本講為所有人設立 **必備五件套**：

```bash
# 逐行看 asm（-M intel 且不會 mangled）
objdump -d -M intel ./pwn    > disasm.txt
# 確定所有「外部函數 → system 的 複雜組合」
readelf -r ./pwn   # 所有 GOT/PLT
# 運行時追蹤
strace -f ./pwn 2> trace_sys.txt
ltrace ./pwn     2> trace_libc.txt
# 動態斷點
gdb ./pwn
(gdb) b *0x1245       # execute 後 execve 前斷
```

> 加入 **`ctypes`/`Ghidra`/`ida`** 這一段以後，可以被称为「靜態+動態」完整的 Pwn 工具箱。

## 6 · 課堂練習

練習 34（Pwn 命令注入）：
